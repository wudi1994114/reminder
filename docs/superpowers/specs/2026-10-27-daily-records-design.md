# 日历每日记录设计

用户已选择先记录自己，保持入口简洁。

## 使用流程

- 在现有小程序日历选中日期下方增加「每日记录」，保留原提醒列表和添加提醒入口。
- 展示当日体重、当日或此前最近一次身高、备注摘要。三个字段均可单独填写，身高不占行显示测量日期。
- 点击体重或身高弹窗展示对应变化图表，右上角「×」关闭；点击备注或右侧「记录 / 编辑」展开就地编辑，支持数字键盘、最长 10000 字备注、保存和收起。
- 身高最近值仅作展示和输入提示，不自动写成当天测量；清空身高后，回退显示该日期以前最近测量。
- 草稿按账号和日期隔离，切换日期、关闭编辑器、离开页面仍可恢复；账号切换立即隐藏旧账号数据。
- 保存失败保留输入并明确重试；多设备冲突不覆盖新数据。已有记录可确认删除。日历提供有记录日期的小标记。
- 沿用现有日历浅米色、暖黄色和系统字体，不新增底部导航，不修改拼豆、音乐和训练模块。

## 紧凑布局修订

根据用户对纵向空间占用的反馈，常态展示改为两行：体重与身高同行，备注另起一行；未填写身高时沿用此前记录，不显示测量日期。去掉重复的「每日记录」视觉标题，编辑入口放在数值行右侧。变化曲线仅在点击指标后弹窗显示，不撑高首页，具体见 measurement-trends 设计。

月历按实际需要显示 4–6 周，不固定塞入第 6 周；日期点击区域保留 44px 高度。日期标记图例与选中日期共用一行。「添加提醒」放在提醒标题右侧，无提醒时状态也在该行内显示，取消独占底部的添加按钮栏。

编辑状态的标签与数字输入合并为同行控件，备注字数与标签同行，输入区域初始高度 88px，长内容在输入框内滚动。保留所有草稿、保存、删除、冲突处理和账号隔离逻辑。390px 宽实测记录区由 248px 降至 104px，月历由 449px 降至 304px；320px 宽短备注常态也无需横向滚动。

## 数据与接口

独立 daily_record 表，用户和日期唯一；体重 kg、身高 cm，最多一位小数；备注纯文本。体重范围 0.1–999.9，身高范围 0.1–300.0，允许字段为空但拒绝全空保存。使用不可复用的记录 ID 加版本号保护并发更新，删除后重建也不能被旧请求覆盖；草稿保留原记录 ID 和版本。

- GET /api/daily-records?month=2026-10：当前账号该月记录。
- GET /api/daily-records/2026-10-27：`{record, latestHeight}`，最近身高只查询该日及之前。
- GET /api/daily-records/trend?metric=weightKg&end=2026-10-27&days=30：返回当前账号范围内的真实测量点，仅含 recordDate 和 value；支持体重/身高以及30/90/365天。
- PUT /api/daily-records/2026-10-27：`{weightKg,heightCm,diary,version,recordId}`，首次 version/recordId=null，后续携带读取 ID 和版本；返回保存记录。
- DELETE /api/daily-records/2026-10-27?version=0&recordId=1：删除当前账号当天记录，ID 或版本冲突返回 409。
- record 字段：id、recordDate、weightKg、heightCm、diary、version、createdAt、updatedAt。latestHeight 字段：recordDate、heightCm。

用户身份只取认证上下文。前端沿用 src/api/http.js 的真实配置地址。每日记录接口请求/响应正文不得写入通用请求日志。数据库升级使用单独的增量 SQL；不对生产执行首次初始化 schema.sql。

## 验收

后端验证日/月查询、账号隔离、按日期取身高、更新不重复、数值及文本限制、冲突保护和删除。前端验证日期和账号草稿隔离、请求乱序、失败重试、保存删除、空字段及历史身高语义。构建 H5 和微信小程序，浏览器检查窄屏及长备注；本地结果与上线/真机验收分开报告。
